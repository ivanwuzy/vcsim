# 具身VC投资模拟器

Next.js、React、TypeScript、Tailwind CSS 与 PostgreSQL。所有评分、时间线与抽奖在服务器完成。当前内置题库为v4.4的50个国内真实公司案例；正式和测试活动均可使用当前题库直接启动。后台可反复新建、删除、启动和停止活动，同一时间仅有一场进行中的活动。

## 本地运行

需要 Node.js 22 或更高版本。

```bash
npm install
cp .env.example .env.local
# 设置独立的 ADMIN_PASSWORD、至少32字符的 SESSION_SECRET
npm run dev
```

本工作区已生成 `.env.local`，不需要覆盖。管理密码保存在该文件中，未提交到代码。玩家入口 `http://localhost:3000`，后台 `/admin`，排行榜 `/leaderboard`，现场大屏仅从主办方工作台的“打开现场大屏”进入（`/admin/screen?event=<活动ID>`，需后台登录），玩家排行榜不提供大屏入口。无 `DATABASE_URL` 时使用 `.data/postgres` 中的本地 PGlite，仅适合单进程本地演示；生产正式模式必须配置真正的 PostgreSQL。

本地测试支持同一协议、同一端口的 `localhost`、`127.0.0.1` 和 IPv6 回环地址；开发服务使用 `0.0.0.0` 监听时不会误拒绝本机访问，无需为每个测试端口修改 `PUBLIC_URL`。其他来源仍须匹配站点或配置的公开地址。

```bash
npm run typecheck
npm test
npm run simulate
npm run build
npm start
```

## 游戏与服务约束

- 本金2亿元、默认每笔500万元，最高4000万元（基金本金的20%），拖动底部横向滑轨，在8个档位间按500万元一档调整，所选金额在翻牌、跳过和刷新后持续保留，每局按固定时间线依次展示全部50家，最多投资20家，可以少投或全不投。未投本金原值计入终值；投资按实际选定金额扣款和结算，滑轨上限随剩余本金收缩，已选金额超出余额时自动调低，服务端拒绝超额投资，投资回款不增加投资名额。
- v4.4包含50个真实案例：具身、其他机器人、核心部件、自动驾驶、芯片、AI模型与应用、AI infra、量子、脑机和商业航天；全部为国内公司。
- 保存后仅前进，不能预看、撤销或编辑组合。第20笔投资保存后立即提示已完成基金投资并结算，余下项目不再呈现；本金提前全部投完也立即结算；否则看完50题后结算。复盘仅含已看过的项目，并展示未遇到项目数量。
- 所有玩家使用同一条完整时间线和固定收益路径。同年按稳定ID排序，种子不影响项目顺序或市场提示。v4.4使用decisionYear表示选定投资进入年份；旧题库兼容foundedYear、firstFundingYear和示例year。
- 2031年统一模拟结算，压缩不同历史跨度；不预测真实2031估值。不计稀释、分红、税费、清算优先权或现金利息，倍数精度为万分之一。
- 仅当前卡片通过玩家接口下发。HttpOnly签名Cookie持有玩家凭证；重复身份不会凭姓名自动接管，需要原设备或工作人员发放一次性恢复码。
- 试用时可在后台“活动 → 试用设置”开启“再玩一次”，全局控制所有玩家的顶部按钮，默认隐藏。点击后清除本场实名登记、进度、成绩和设备上的本场游戏缓存，返回首页重新登记；可使用原姓名与机构重新开始。开关约5–7秒同步到可见的玩家页面，关闭后服务端也禁止重置。
- 幂等决策键与行锁防止并发重复提交。所有写操作检查Origin；后台登录限流、8小时会话，数据库不通过公开接口暴露。
- 新建活动不会改变公共入口；启动任意活动会自动停止此前进行中的活动。首页、旧活动链接、二维码和公共榜单始终对应唯一进行中的活动。没有进行中的活动时显示等待提示，已打开页面自动更新。
- 停止活动会暂停新登记和答题，保留已有进度与成绩；重新启动后可继续。冻结固定完成者排名供抽奖使用；重新启动已冻结活动时保留题目和成绩、解除冻结并清除旧抽奖结果。
- 删除活动同时删除其玩家、游戏和抽奖记录。删除进行中的活动后，公共入口等待主办方启动另一场；可删空全部活动，再新建。系统当前题库与删除操作记录保留。历史榜单和颁奖大屏通过后台查看，公共榜单仅显示当前活动。
- 每批抽奖持久化请求键、候选池、获奖名单；排名奖边界抽签独立，幸运奖默认跨批次去重。现场大屏和工作台共用卡通老虎机浮窗：点击摇杆先在服务端保存结果，再从左到右播放揭晓动画与庆祝特效；关闭、重开及刷新可回看中奖名单。重抽须二次确认，替换最新一轮并保留其他轮次；追加抽取可选择人数及是否排除已中奖人员，同一轮始终不重复。网络异常重试沿用同一次请求键。CSV导出只计有效奖项，并防止姓名字段触发表格公式。

## 题库及审校

`data/projects.ts` 从 `具身VC投资模拟器_题库v4.4.xlsx` 生成，使用 `python3 scripts/import-question-bank.py`，再运行 `npm run export-content` 更新JSON与Markdown导出。`data/question-bank-manifest.json`记录原表SHA256与逐公司进入年、结算倍数。三张表按公司名称匹配，并核对案例ID；不依赖行序。原Excel不修改。

卡片与页面“当前年代”采用题库底稿F列“游戏进入年份”，新活动按此年份排序。回报测算C列仅作为估值测算进入年保存在valuation.entryYear，K列“结算倍数”为人工确认回报；I列人工指定倍率优先，否则同币种终点估值÷进入估值×持股保留系数。导入时复算并核对公式缓存，遇到缺值、重复公司、ID冲突或缓存不一致即停止。v4.4全部50家已人工确认结算设置，分布为44个增值、6个0.1倍损失回收；人工确认不表示全部同期事实已审校。旧研究口径及题库底稿的近似倍数不影响结算。v4.4首次导入误用测算进入年作为卡片年；本次对同一原表的已参赛快照只修正卡片年份，保留既定出题顺序、估值、收益路径、决策和成绩。美元保留原币，倍数取万分之一，2031年仅为模拟统一结算年。

原型团队、技术、商业故事、信息边界及人工标记保存在editorial，仅供后台使用；玩家卡片仅包含原表游戏字段与进入参考。人工确认文案不等同来源事实全部审校，review仍保留draft。

正式内容负责人逐题核验卡片信息当时可得、历史结局与法人边界，并补充：

- `sources[].url`：具体报道、原始公告或披露文件，不只填官网入口。
- `sources[].publishedAt`：真实发布日期，`YYYY-MM-DD`。
- `decisionEvidence`：与某个来源URL一致，且该来源年份不晚于决策年份。
- `reviewedAt`：实际审校日期；`review: "approved"`：人工审校通过。

后台导出JSON、修改后导入**未开放活动**，即可更新系统当前题库。新建活动和首次启动活动采用当前版本；规则升级会更新尚未开始的活动，恢复已经开始过的活动沿用原快照，保留进度与成绩。修改内置题库源码后，新版本同样成为系统当前题库。

正式和测试活动均不受审校状态、审校时间、同期证据或内容计划检查的启动限制；后台仍展示这些信息供持续优化。导入仍须满足JSON结构和能生成50题固定时间线的要求。存量已参赛活动不会被改写；升级时若有多场开放活动，只保留最近一场进行中，其余停止并保留数据。

模拟收益不等于真实公司的实际投资回报。玩家接口只下发当张卡片及进入参考估值，展示层隐藏案例人名并模糊部分团队机构线索；真实名称、终值估值、历史与来源只在终局披露。历史存量活动沿用原快照规则，不重新计算已参赛成绩。

## 部署

生产站点为 https://vcsim.ootoday.top ，部署在 Vercel 的 `zyqfwyh/embodied-vc-simulator` 项目，数据库使用 Supabase PostgreSQL（Seoul），通过官方集成同步平台配置，应用使用共享事务连接池。

源码仓库为 [ivanwuzy/vcsim](https://github.com/ivanwuzy/vcsim)，公开可见。Vercel 的同一项目连接此 GitHub 仓库，以 `main` 为生产分支；推送到 `main` 后由 Vercel 自动构建和发布，沿用现有生产环境变量、Supabase PostgreSQL 和域名。官方 Vercel GitHub App 的仓库授权范围仅为 `ivanwuzy/vcsim`。

本地更新流程为 `git add <修改的文件>`、`git commit -m "描述修改"`、`git push origin main`。实际密钥保存在本地 `.env.local` 与 Vercel 环境变量中；`.gitignore` 排除本地环境变量、数据库、依赖、构建缓存与测试产物。仓库保留题库导入需要的 v4.4 原始 Excel（另保留历史v3原表），同时保留本地已有的历史题库工作簿；其他 `outputs` 研究产物和线上备份不提交。新环境可通过 `git clone https://github.com/ivanwuzy/vcsim.git` 获取项目，并执行 `npm ci`。

发布后核对Deployment为Ready、域名指向新部署、`/api/meta`的contentVersion/yearBasis及后台导出的50题与本地清单一致。未参赛兼容场次自动更新；已参赛场次保留题库和成绩，需创建新v4.4场次并启动以让公共入口使用新题库。后台开启场次会停止此前开放场次并保留数据。

`deploy/`与compose配置保留为可选VPS方式；当前线上不使用该方案。

活动主持操作见 `docs/活动操作说明.md`；当前验证范围见 `docs/验证记录.md`。

Neon网络额度排查及百人访问预算见 [Neon成本排查与优化](docs/Neon成本排查与优化.md)。状态轮询只读取元数据；题库按数据库维护的内容版本缓存，每次仍读取活动状态。公共状态和公共榜单缓存2秒，登录会话、个人游戏和后台接口不使用公共缓存。隐藏标签页暂停轮询，网络失败后退避至最长60秒。Neon部署应使用带`-pooler`的连接地址；应用每个实例最多4条连接，空闲5秒释放。数据库的自动休眠仍取决于实际访问和平台设置。

Supabase 使用端口6543的共享事务连接池，`DATABASE_SSL_CA` 配置从数据库设置下载的官方根证书 PEM，始终校验证书及主机名。保留原 `SESSION_SECRET` 与 `ADMIN_PASSWORD`，以延续玩家及后台会话。应用七张表启用RLS，撤销anon/authenticated权限，Data API保持关闭。迁移及恢复步骤见 [数据库迁移](docs/数据库迁移.md)。
