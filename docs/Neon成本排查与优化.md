# Neon成本排查与优化

排查日期：2026-10-15（北京时间）。本次优化保存在本地，尚未发布或变更线上套餐、计算资源配置。题库Excel的已有本地修改不属于本次变更。

## 结论与线上证据

此次停服由**网络传输额度耗尽**触发。Neon控制台明确显示“You've used all of your monthly network transfer allowance for this project”。组织页面显示自10月13日以来传输6.17 GB、计算5.04 CU-hours、存储0.03 GB；项目页面稍后显示传输6.19 GB、计算5.1 CU-hours、存储33.54 MB，默认计算0.25 CU。两处统计有刷新延迟，不能据此计算分钟级增速。

项目当前为Free，账期为2026-10-13至2026-11-01。Vercel日志中，`/api/meta`约每3秒、`/api/admin/leaderboard`约每5秒重复报错，Postgres错误码为`53000`，消息为账户或项目超过额度。额度用尽后原客户端仍持续请求。

依据当日[Neon官方套餐文档](https://neon.com/docs/introduction/plans)和[价格页](https://neon.com/pricing)：Free每项目每月含5 GB公网传输、100 CU-hours；Launch和Scale每项目含500 GB公网传输，之后$0.10/GB。Launch计算为$0.106/CU-hour、Scale为$0.222/CU-hour，计算及存储等按量计费。Vercel原生集成的订阅由Vercel管理，实际升级页面和账单为准。

## 为什么少量访问也会耗尽

旧版`components/game.tsx`每3秒请求`/api/meta`。`publicMeta()`通过`getActiveEvent()`执行`SELECT * FROM events`，从Neon传回整份JSONB快照，再由应用选出少量元数据。当前v4.2快照的紧凑JSON为288,927字节，其中项目题库203,557字节。玩家收到的HTTP响应虽小，**Neon到Vercel的完整快照已经计入数据库出口流量**；网页压缩无法消除这段流量。

按快照尺寸估算，旧版仅状态轮询为：

| 场景 | 每小时数据库出口数据量 |
| --- | ---: |
| 1个页面持续轮询 | 约0.35 GB |
| 100个页面持续轮询 | 约34.7 GB |

这是紧凑JSON的估算，未计协议开销、其他接口和历史场次的不同快照尺寸。6.19 GB相当于约18个页面小时，少量标签页累计打开数小时就能产生这个量级；没有历史逐请求计量，因此不能把全部流量精确归因到某个用户或标签页。

榜单、个人结果和游戏请求也重复读取快照。原版一次决策在路由检查当前活动和事务读取活动时各传回一次完整快照；本次压测的3,500次决策，仅这两处旧读法就约2.0 GB。隐藏页面、后台及大屏的轮询没有暂停逻辑，且失败后继续固定频率重试。高频查询也延长数据库活跃时间。

## 已完成的本地优化

1. `/api/meta`在Postgres内投影规则、活动信息、时期提示和重玩开关，查询结果约1.1 KB，不传回项目题库、收益路径、牌组。匿名`/api/session`使用同一元数据查询；路由验证游戏所属活动只查当前活动ID。
2. 公共榜单不再读取完整活动快照。公共状态和公共榜单各有2秒进程缓存、并发请求合并和CDN缓存头。登录会话、游戏、个人结果、后台与受保护大屏接口保留`no-store`。成功的活动管理、重置和结算会清除本实例的公共缓存，其他实例及CDN最多有短暂刷新延迟；写操作检查始终直接访问数据库。
3. `getEvent()`先读取实时活动头部，再按`活动ID + snapshot_revision`复用题库快照，缓存最多16份。数据库触发器在插入或修改快照时计算内容指纹，覆盖导入、升级、直接SQL和事务回滚。状态、冻结榜单和设置不从快照缓存读取；评分、幂等和行锁保留。
4. 玩家状态轮询改为5秒，结果轮询30秒，榜单5秒、后台10秒。所有数据轮询在页面隐藏时暂停、回来时立即刷新；同一轮询不重叠，失败后指数退避至最长60秒。后台开关正常情况下约5–7秒同步，弱网和故障时可能更慢。
5. `pg`池改为每实例最多4条连接，空闲5秒释放，连接超时10秒、最长连接寿命300秒；处理空闲连接错误。新增玩家token索引。此池限制是**每实例**的，Vercel多实例仍应使用Neon的`-pooler`连接地址。

缓存不是全局持久层：Vercel冷启动、实例数量、CDN区域与写入频率都会影响命中率。即使缓存完全未命中，元数据查询也只传回必要字段。首次初始化及新快照仍需访问数据库；运行中的旧部署也须更新才能获得优化。

## 百人活动预算与后续操作

按当前约1,095字节的数据库元数据结果、5秒轮询，100个可见游戏页面每小时约**0.079 GB**，即使没有缓存，约为旧版状态轮询的1/440。实际还要增加答题、榜单、结果、后台、冷启动和同月其他访问；不能据这一项承诺免费套餐永不超额。

全量榜单仍随人数增长。示例：若100行榜单一次数据库查询结果约12 KB，100人持续每5秒刷新且公共缓存完全未命中，则仅榜单数据约0.86 GB/小时；短缓存命中后可大幅减少，真实值取决于姓名机构长度与实例数量。活动时长、每天开放时长和每月场次比“100人”本身更能决定成本。

建议执行顺序：

1. **先发布本次优化，再考虑扩容。** 仅购买更大套餐会掩盖重复传输问题。此次Free额度已经消耗完，本地代码不能返还额度；当期恢复需由账户持有人在Vercel管理的Neon订阅中选择付费恢复，或等待配额重置。此过程尚未操作。
2. 发布前核对生产`DATABASE_URL`确为`-pooler`地址；保留自动休眠，避免监控每分钟直接访问数据库。计算下限可从0.25 CU起步，最大值按真实隔离Neon压测确定，不单凭本地157 ms就设置生产容量。
3. 正式百人活动优先使用有余量的付费方案；设置支出提醒并核对它是否只是通知、是否有可用的强制上限。当前官方Launch是按量计费，不存在所有费用都包含在一个固定免费额度里的保证。例如0.25 CU连续活跃约730小时，约182.5 CU-hours，单计算约$19.35/月；Free的100 CU-hours也不足覆盖这种常驻访问。实际会随休眠和自动扩容变化。
4. 额度恢复并发布后，在**独立Neon测试分支或测试项目**运行100人注册、答题与持续轮询，记录活动前后Network transfer/CU-hours差值和P95延迟；等指标延迟窗口后再读数。确认公共接口CDN命中、私有接口未共享缓存、停止活动后决策立即被拒绝，才把生产容量视作已验证。
5. 以实测“GB/场 × 月场次 + 日常试用”和“平均CU × 活跃小时”制定预算，预留至少一倍余量。活动结束关闭或离开测试游戏/后台/大屏，已打开的旧版本页面需刷新。页面持续可见轮询仍会保持数据库活跃，因此停止活动本身不保证休眠。

这些操作尚未配置定时任务、支出提醒、付费套餐或生产计算资源，也没有发送第三方消息。
