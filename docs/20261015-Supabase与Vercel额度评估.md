# Supabase 与 Vercel 免费额度评估

核查时间：2026-10-15 约22时，北京时间。核查方式为平台控制台、Vercel 只读项目 API、Supabase 只读 SQL 和少量公共 GET。没有修改套餐、部署、数据库内容，也没有运行线上压测。

## 结论

当前两个平台的实际用量都很低。两次15人测试通常能够继续；但按150人正式互动5小时、两次15人各开放24小时的安排，不能承诺免费套餐安全覆盖全程。页面是否持续可见，比活动开放时长本身更影响用量。

- 若参与者每人只玩约1小时，随后关闭页面，额度风险较低。
- 若15人每次测试都持续可见24小时、正式150人持续可见5小时，游戏与结果页轮询约124万次，超过Vercel 100万次免费CDN请求额度；缓存命中也计入CDN请求。实际还有登记、答题、静态资源、管理后台和同团队其他项目。
- Supabase 5 GB数据库出口额度，在结果页长期打开场景下余量不宽；全员持续查看榜单且公共缓存失效时，单正式活动榜单可超过5 GB。当前缓存短测有命中，但不能拿单一区域几次命中作为全场保证。
- 建议正式活动前采用Vercel Pro。为了现场稳定性，Supabase Pro + Micro也更稳妥；是否升级Supabase可结合首轮测试后的真实流量差值决定。没有进行任何升级操作。

## 活动预算

当前代码：游戏状态每5秒刷新；完成后仍保留该状态轮询，同时每30秒刷新一次完整个人结果；公共榜单和大屏每5秒；后台每10秒。页面隐藏暂停，失败指数退避；停止活动不自动关闭可见页面的轮询。一次轮询结束后才开始计时间隔，下列按720次/小时和120次/小时计算略偏保守。

| 场景 | 可见人小时 | 状态请求 | 结果请求上限 | 合计轮询 |
| --- | ---: | ---: | ---: | ---: |
| 正式150人×5小时 | 750 | 540,000 | 90,000 | 630,000 |
| 测试15人×24小时×2次 | 720 | 518,400 | 86,400 | 604,800 |
| 合计 | 1,470 | 1,058,400 | 176,400 | 1,234,800 |

结果请求上限将所有时间都按已完成计算，实际答题期不产生结果轮询。即使完全去掉结果轮询，状态请求上限106万次也已超过100万。180人次每人一局最多再产生9,000次决策请求，另有注册、开始、页面资源与工作人员操作。两次测试结束后，约60.5万次轮询加目前3.1万次CDN请求，理论只剩约36.4万次；正式150人的结果页按每人840次/小时，约2.9小时即可吃掉这部分余量。实际耗尽时间受页面可见性、答题时长和请求延迟影响。

相反，若180人次每人只打开1小时，轮询约151,200次，加目前31,000次、答题和资源后仍明显小于100万。仅开放活动24小时，没有用户访问不会产生这720人小时。

### Supabase出口估算

数据库连接池出口计入非缓存Egress；Vercel CDN命中或应用缓存可以减少数据库访问，但它们不会把数据库出口变成Supabase Cached Egress。

- 元数据数据库查询当前约1.1 KB。完全不命中缓存时，1470人小时的状态轮询约1.16 GB。
- 结果接口每次重新读取单局进度、玩家、活动头部和全体已完成榜单。按当前行尺寸、150人全部完成和约5 KB单局，正式90,000次结果轮询约2 GB量级；两次15人测试结果轮询约0.6 GB量级。
- 两项加起来约3.8–4.1 GB，再加题库冷启动、答题、后台、协议开销与同账期其他访问，5 GB余量偏紧。缓存命中和较少可见时长会降低实际值；这些是结构与字节估算，不是Supabase计费实测。
- 若150人都查看5秒刷新的全榜单、所有人都已完成且完全没有缓存，仅榜单行数据约9.3 GB/5小时；两次15人满24小时约0.89 GB。该场景替代游戏/结果页，不能将它们重复相加。公共缓存正常会明显降低数据库出口。
- 少量题库快照、180人次的进度与成绩远小于剩余473 MB数据库空间，存储不是首要风险。反复修改产生的表膨胀会影响实际磁盘，但本次规模没有证据表明会触及500 MB。

### Vercel流量与函数预算

结果接口并不只返回排名；每次包含完整复盘项目字段和高亮项目。针对当前生产题库，在只读SQL获取快照后按现有结构计算复盘主体尺寸：

| 已看题数 | 未压缩JSON | gzip | Brotli |
| --- | ---: | ---: | ---: |
| 20 | 116,222字节 | 24,230字节 | 17,050字节 |
| 35 | 192,587字节 | 38,572字节 | 27,193字节 |
| 50 | 265,027字节 | 51,952字节 | 36,934字节 |

这是使用三条高亮的复盘主体测量，不是完整响应或账单；实际题数、投资决策和高亮数量会变动。

按176,400次结果请求，主体未压缩合计约20.5–46.8 GB，gzip约4.3–9.2 GB，Brotli约3.0–6.5 GB。公共GET实测终端可获得Brotli。**不能据终端压缩比推定Fast Origin Transfer按同样比例计费**；它统计计算服务与CDN间的双向数据，且后台10秒刷新还会返回题库快照。因此100 GB终端流量总体较宽，10 GB Origin额度需要重点观察，不能用“网页已压缩”保证不超额。

函数调用只有缓存未命中的请求才计入。假设完全没有CDN命中，124万次轮询也超过100万函数调用；正常公共缓存会减少函数次数，却不减少CDN请求次数。私有结果和后台保持no-store。

用当前约29,000次函数调用、7分54秒CPU计算，历史平均约16毫秒CPU/调用。机械外推124万次约5.6 CPU小时，也超过4小时；但历史包括旧版、故障与管理操作，不能当成新生产版本预测。当前0.72 GB小时也不能用来证明150人并发没有容量问题。已有100人测试使用本地PGlite，不是Supabase公网压测。

## 建议

1. 两次15人测试可以先正常开展，玩完退出或切到隐藏页；不要让15个结果页持续显示整天。后台和大屏也只在需要时保持可见。
2. 正式活动前将Vercel升级Pro：官方当前价格$20/月，含$20资源使用抵扣；额外费用与平台支出配置以账户页面为准。Hobby官方仅允许个人非商业用途，当前公司组织的正式互动也应采用Pro。
3. Supabase如需尽量降低现场风险，采用Pro $25/月和Micro。Pro含250 GB非缓存出口，8 GB磁盘与$10计算抵扣，可覆盖一台Micro的通常月度计算。升级组织后不保证自动将已有Nano变为Micro；计算规格变更可能有短暂停机，应提前完成并验证。Micro也不是150人并发性能保证。
4. 若希望继续控制成本，优先优化结算页：复盘只首次获取，排名用小响应单独刷新；等待页状态可放缓。后台避免每10秒重复返回整份题库。此处只是建议，本次没有修改代码或部署。
5. 首次测试前后记录Supabase Egress和Vercel CDN请求、Origin流量、Active CPU差值；Supabase至少给统计1小时刷新时间。按真实可见页面小时外推，并预留一倍活动预算余量。10月27日再次人工核对余量和错误日志。
6. 在独立测试活动上验证150人注册/答题、若干结果页与大屏轮询的真实公网延迟、失败率和连接峰值，再判断Nano/Micro是否足够。压测会写入测试记录和消耗线上额度，本次未执行。

推荐正式活动费用基线为Vercel Pro $20 + Supabase Pro $25，即约$45/月（税费、额外席位或资源超用不含）。这是可靠性选择，不表示两次普通测试立即需要付费。
