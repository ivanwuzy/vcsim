# 数据库迁移与恢复

生产应用通过服务端 `pg` 访问 PostgreSQL。Supabase 平台集成同步 `SUPABASE_*` 等配置，应用实际连接以 `DATABASE_URL` 为准。在线请求使用共享事务池6543；迁移使用共享会话池5432，配合官方根证书校验TLS。不要把服务端数据库密码或服务角色密钥放入客户端环境变量。

迁移前保存平台配置和源库快照，在暂停写入期间对七张表作一致备份：events、players、runs、draws、audit_log、rate_limits、game_settings。备份每行保存PostgreSQL生成的JSONB原文，避免JavaScript转换丢失BIGINT和微秒时间戳；每表记录行数和SHA256。所有备份与凭据仅保存在Git忽略的 `backups/` 中，权限限制为当前用户可读写。

将 `MAINTENANCE_MODE=1` 发布到线上后，所有API请求在连接数据库前返回503、no-store和Retry-After。确认没有后台编辑和旧部署写入，补做最终源库备份，再导入空目标库。备份应保留迁移前活动的开放状态。

```bash
DATABASE_SSL_CA_FILE=/protected/supabase-ca.crt npx tsx scripts/restore-database.ts restore /protected/database.json /protected/session-url.txt /protected/restore-report.json
DATABASE_SSL_CA_FILE=/protected/supabase-ca.crt npx tsx scripts/restore-database.ts verify /protected/database.json /protected/session-url.txt /protected/verify-report.json
```

恢复脚本拒绝覆盖非空目标库或包含其他public表的数据库；在事务中创建应用结构、恢复原列、开启RLS并撤销匿名权限。提交前校验每表行数及原列SHA256；任何失败整体回滚。新增snapshot_revision列由数据库触发器维护，不改变原始活动题库。恢复报告仅包含计数、校验值和数据库版本，不包含玩家身份或密码。

导入校验通过后，将Vercel的 `DATABASE_URL` 指向目标事务池并设置 `DATABASE_SSL_CA`，保留会话密钥；断开Neon资源与应用项目的绑定，保留Neon库和快照。将 `MAINTENANCE_MODE=0` 重新发布，验证主域名、原玩家会话、历史榜单和实际读写。不要对仍在承接流量的目标库重复运行原备份校验并要求完全一致，因为上线后的合法写入会改变数据。

回滚时先重新进入维护模式，备份Supabase中新产生的数据；只有确认目标库没有新增写入，或完成新数据回迁后，才能恢复Neon连接与原开放活动。不能直接回滚到旧备份丢弃迁移后进度。保留原库并不等于免收费；付费方案需在确认留存需求后由账户所有者调整。
